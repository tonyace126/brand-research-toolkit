# Design Spec: brand-research-toolkit

**Date**: 2026-05-15
**Author**: Tony Wang / Sugarfun
**Status**: Approved (brainstorming complete, awaiting implementation plan)

---

## 1. Purpose

A downloadable Claude Code plugin packaging two reusable skills:

1. **`brand-issue-research`** — research brand topics, controversies, or campaigns across Taiwan-relevant platforms (YouTube, PTT, Dcard, Mobile01, news, Threads, FB) with parallel agent dispatch and structured output.
2. **`publish-research-html`** — convert any research result into a clean responsive HTML newsletter and optionally auto-push to a GitHub Pages repo.

**Target audience**: 進階 marketing 使用者（會用 ChatGPT/Gemini，但不一定碰過 Claude Code）/ 喜歡當伸手牌的你。

**Distribution**: 公開 GitHub repo `brand-research-toolkit`，clone 即用。

---

## 2. Scope

### In Scope
- 跨平台品牌議題研究方法論（不限影片，含論壇/新聞/社群）
- 各平台對 AI 真實可達性的誠實標註
- 並行 agent 分派範本
- 統一輸出表格 schema
- 通用乾淨 HTML 範本 + CSS 變數客製化系統
- 一次性互動式 setup 寫入 `~/.config/research-publisher.json`
- 自動 git push 到使用者 GitHub Pages repo

### Out of Scope (v1)
- 自動更新首頁 index.html / 文章索引（每人邏輯不同）
- RSS feed / email 訂閱整合
- 多套 layout 範本（電子報 / 報告 / dashboard）— 僅一套通用 layout
- IG/FB/TikTok 的「假爬蟲」教學（誠實註明 AI 走不通）
- `.plugin` 打包（v2 再加，視 Cowork plugin 系統穩定度）

### Communication between skills
- 兩個 skill 鬆耦合（loose coupling）：研究 skill 完成後**詢問**使用者要不要發布，使用者同意才觸發 publish skill
- publish skill **不依賴**研究 skill 的特定資料結構，接受任何「標題 + tldr + 主要內容 + 來源」的輸入

### Frontmatter

**brand-issue-research**:
```yaml
---
name: brand-issue-research
description: Research brand issues, controversies, or campaigns across YouTube, PTT, Dcard, Mobile01, news sites, Threads, and FB. Use when user says "research X brand discussion", "find what people say about Y", "track [brand] [topic] across platforms", "盤點 X 品牌話題", "研究 X 在 PTT/YouTube 怎麼被討論", "X 議題輿情", or wants a structured cross-platform brand sentiment / topic landscape. Dispatches parallel agents per platform, returns structured tables + observation summary.
---
```

**publish-research-html**:
```yaml
---
name: publish-research-html
description: Convert any research result (tables, summaries, sources) into a clean, responsive HTML newsletter and optionally auto-push to a GitHub Pages repo. Use when user says "做成 HTML", "推到 my-shares", "publish as newsletter", "把這份報告做成電子報", "發到網頁版" or after completing any research task that should be shareable.
---
```

## 4. Skill 1: brand-issue-research

### 5-step flow
1. **釐清研究主題**：品牌名 / 議題 / 時間範圍 / 競品對照（一題一題問清楚）
2. **平台分派**：根據主題挑要查的平台（不是每次都全查）
3. **並行 dispatch agents**：每平台一個 agent，使用 `references/prompts/parallel-agents.md` 範本
4. **整合結果**：合併成統一表格 schema（`assets/output-schema.json`）
5. **觀察小結**：3-5 條跨平台 insight

### Platform reachability matrix

| 平台 | AI 友善度 | 主要工具 |
|---|---|---|
| YouTube | ✅ 高 | WebSearch + Gemini 餵連結 |
| PTT | ✅ 高（純 HTML） | WebFetch + WebSearch site: |
| Dcard | ✅ 中 | WebSearch site: + Chrome MCP |
| Mobile01 | ✅ 高 | WebFetch + WebSearch site: |
| 新聞媒體 | ✅ 高 | WebSearch + WebFetch |
| Threads | ⚠️ 牆 | 改用 Threads App / KEYPO |
| FB | ⚠️ 牆 | 改用第三方社群監聽 |

### Output schema

統一表格欄位：
```
平台 | 標題/主題 | 來源（頻道/版/作者） | 日期 | 聲量級距 | 情緒 | 主題分類 | URL
```

聲量級距：高 / 中高 / 中 / 低（無法精確驗證時用級距取代假數字）
情緒：正向 / 中性 / 負向 / 爭議

### Strict rules
- **找不到就說找不到**，禁止編造影片、貼文、URL
- 每個平台至少嘗試 3 種搜尋組合
- 必須保留可點開的原始 URL
- 每個 agent 回傳長度上限約 800-1000 字（防止 context bloat）

### references/ 子文件預期內容
- **platforms/youtube.md**（500 字）：搜尋語法、Gemini 餵連結提示詞、軟化版 prompt（避免拒絕）
- **platforms/ptt.md**（300 字）：PTT 看板挑選、site:ptt.cc 語法、批踢踢實業坊 vs disp.cc 鏡像
- **platforms/dcard.md**（300 字）：版選擇邏輯、Chrome MCP 可用性、API 端點（若有）
- **platforms/mobile01.md**（300 字）：3C/汽車/家電專區搜尋技巧
- **platforms/news.md**（300 字）：UDN/ETtoday/Yahoo/Mirror Media 等可 WebFetch 的來源清單
- **platforms/threads-fb.md**（500 字）：誠實說明 AI 走不通的原因 + 建議改用工具（KEYPO、KOL Radar、原生 App）
- **prompts/parallel-agents.md**（400 字）：dispatch 範本、軟化語氣、輸出格式約束
- **examples/bank-research-2026-05.md**（800 字）：把這次的銀行研究包成完整教材

## 5. Skill 2: publish-research-html

### 4-step flow
1. **讀設定檔** `~/.config/research-publisher.json`（不存在則跑 setup）
2. **整理輸入**：標題、tldr、主表格、補充內容、來源清單
3. **套用範本** `assets/newsletter-template.html` + `assets/theme-vars.css`
4. **產出 + 詢問是否 push**

### Config file format

`~/.config/research-publisher.json`:
```json
{
  "shares_repo_path": "/Users/xxx/my-shares",
  "shares_base_url": "https://xxx.github.io/my-shares",
  "default_author": "Tony / Sugarfun",
  "theme_overrides": "sugarfun-theme.css"
}
```

### Setup flow（5 questions）
1. GitHub Pages repo 本機絕對路徑
2. 對外網址
3. 作者署名
4. 是否要自訂主題（y/n）
5. 自訂主題 CSS 檔名（放在 repo 根目錄）

寫入後做一次模擬產出測試（不真的 commit），驗證可寫、git 可 push。

### HTML template

單檔響應式 HTML，內嵌 CSS。CSS 變數設計：
```css
--color-bg, --color-text, --color-muted, --color-accent, --color-border, --color-card
--font-sans
--max-width, --radius
```

範本占位符（mustache 風格）：
```
{{TITLE}} {{TLDR}} {{AUTHOR}} {{DATE}} {{YEAR}} {{READ_TIME}}
{{HOME_URL}} {{BODY}} {{SOURCES}} {{THEME_OVERRIDE_LINK}}
```

### Naming convention
- 英文 kebab-case + 主題明確
- 好：`2026-05-tw-bank-viral-videos.html`
- 爛：`research.html`、`report-final-v2.html`
- **不動 index.html**（首頁邏輯使用者自管）

### Push flow
1. 產出後先 preview HTML 路徑給使用者
2. 詢問「Push 到 GitHub Pages 嗎？」
3. 同意：`cd repo && git add <file> && git commit -m "Add: <title>" && git push`
4. 給對外網址 + 提醒 1-2 分鐘部署

## 6. Language strategy

- **SKILL.md 主體 + references/**：繁體中文

## 8. Error handling

| 情境 | 處理 |
|---|---|
| Agent 找不到資料 | 表格寫「該平台近 X 天無顯著內容」，不編造 |
| WebFetch 被擋（IG/FB/Threads） | 切換到對應平台手冊建議的替代工具 |
| `~/.config/research-publisher.json` 不存在 | 跑互動式 setup |
| repo 路徑不存在 | 提示使用者先建 GitHub Pages repo，連 setup 指南 |
| git push 失敗 | 顯示錯誤、保留 HTML 檔、不刪除使用者資料 |
| theme_overrides 檔案不存在 | 警告但繼續產出（用預設主題） |

## 9. Testing approach

**v1 不寫自動化測試**（skill 是 prompt + markdown 為主），改靠：
- 手動驗證流程：跑一次完整銀行研究 → 發布 → 確認 my-shares 網址可開
- 範本相容性：HTML 範本在 Chrome / Safari / 行動瀏覽器手動檢查
- 範例輸出 `examples/2026-05-tw-bank-viral-videos.html` 兼當 regression 樣本
